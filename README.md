# DALI PAY 💜

> שני אידיוטים. מאזן אחד.

אפליקציית Android לניהול חובות ומוצרים בין דוד לאלי, עם סנכרון אוטומטי בזמן אמת בין המכשירים.
כל הממשק בעברית ובכיוון RTL.

## טכנולוגיה

- **אפליקציה:** React Native + Expo (SDK 58), בנייה ל-APK אמיתי דרך EAS Build.
- **ענן וזמן אמת:** Supabase (PostgreSQL + Realtime + Auth).
- **הרשאות:** Row Level Security — רק חברי הקבוצה רואים ומשנים נתונים. מחיקה מותרת ליוצר הרשומה או למנהל הקבוצה.
- **שמירת נתונים:** הכול נשמר בענן ולא במכשיר. התנתקות, התקנה מחדש או החלפת מכשיר לא מוחקות כלום.

## מבנה

```
App.js                 כניסה, ניווט תחתון, חיבור לקבוצה
src/                   מסכים: חובות, מוצרים, פרויקטים, הגדרות, התחברות
supabase/schema.sql    טבלאות, הרשאות וסנכרון בזמן אמת
assets/                אייקון, אייקון adaptive ומסך פתיחה
eas.json               פרופילי בנייה ל-APK
```

## הקמה חד-פעמית (כ-15 דקות)

### 1. בסיס נתונים ב-Supabase

1. פתח פרויקט חינמי ב-https://supabase.com.
2. SQL Editor ← New query ← הדבק את כל `supabase/schema.sql` ← Run.
3. Authentication ← Sign In / Providers ← Email: **כבה "Confirm email"** (האפליקציה מניחה שההרשמה מחזירה כניסה מיידית).
4. Project Settings ← API: העתק את **Project URL** ואת **anon public key**.

### 2. חיבור האפליקציה

ב-`eas.json` החלף את `PUT_SUPABASE_URL_HERE` ו-`PUT_SUPABASE_ANON_KEY_HERE` בשני הערכים (בשני הפרופילים).
ה-anon key מיועד להיות ציבורי, ההגנה היא בהרשאות ה-RLS שבסכמה.

### 3. בניית APK מהטלפון (GitHub Actions, בלי מחשב ובלי חשבון Expo)

1. ב-GitHub: Settings ← Secrets and variables ← Actions ← New repository secret.
   שם: `KEYSTORE_PASSPHRASE`, ערך: סיסמה שתבחר (לפחות 8 תווים, חזקה). **שמור אותה במקום בטוח** — בלעדיה אי אפשר לעדכן את האפליקציה.
2. Actions ← **Build APK** ← Run workflow.
3. כעבור כ-15–25 דקות ייווצר Release חדש בלשונית Releases, עם הקובץ `dali-pay.apk` להורדה והתקנה.

בריצה הראשונה נוצר מפתח חתימה, מוצפן בסיסמה ונשמר ב-`signing/dalipay.jks.enc` בתוך ה-Repository. בריצות הבאות נעשה בו שימוש חוזר, וכך כל עדכון מותקן מעל הקיים בלי למחוק נתונים. **אסור למחוק את הקובץ הזה או לאבד את הסיסמה.**

בנייה חלופית דרך EAS (דורשת חשבון Expo ו-`EXPO_TOKEN`) קיימת ב-`build-apk-eas.yml` ואינה נחוצה.

## הוראות התקנה בטלפון

1. פתח את קישור ה-APK בטלפון (או העבר את הקובץ).
2. אם Android שואל, אשר "התקנה ממקורות לא ידועים" לדפדפן/מנהל הקבצים.
3. התקן ופתח את **DALI PAY**.

## חיבור משתמש נוסף (דוד ואלי)

1. **דוד:** נרשם באפליקציה (אימייל וסיסמה) ← מזין את שמו ← "יצירת קבוצה".
2. בלשונית **הגדרות** מופיע **קוד הזמנה** — שתף אותו עם אלי.
3. **אלי:** מתקין את ה-APK ← נרשם עם אימייל משלו ← מזין את שמו ← "הצטרפות" עם הקוד.
4. מעכשיו כל חוב, מוצר או פרויקט שמתווסף אצל אחד מופיע מיד אצל השני.

## עדכון האפליקציה בעתיד

1. שנה קוד והעלה commit ל-GitHub.
2. הרץ שוב את Build APK ב-Actions ושלח לשניכם את הקישור ל-Release החדש.
3. התקנה **מעל** הגרסה הקיימת שומרת על הכניסה ועל כל הנתונים (הנתונים בענן).
4. שינויי מבנה נתונים: הוסף קובץ SQL חדש ב-`supabase/` והרץ אותו ב-SQL Editor לפני ההפצה.

## גרסה 1.2 — מה חדש

- **פרויקטים הוסרו מהממשק.** הטבלה והעמודות נשארו במסד הנתונים (אין מחיקת נתונים), והן נכללות בייצוא הגיבוי.
- **חובות:** סכום, סיבה, תאריך יצירה, סטטוס, תשלומים חלקיים (`record_payment`), היסטוריית תשלומים עם מי סימן ומתי.
- **מוצרים:** אצל מי המוצר, למי הוא צריך להגיע, כמות, נמסר/ממתין. נפרד לגמרי מכסף.
- **Bit:** כל משתמש מזין מספר Bit בהגדרות. החייב לוחץ "העבר תשלום ב-Bit": מועתקים הטלפון והסכום, ו-Bit נפתחת (חבילה `com.bnhp.payments.paymentsapp`, ואם אינה מותקנת, דף Google Play). Bit לא מפרסמת קישור תשלום מוכן מראש, לכן אי אפשר למלא תשלום אוטומטית, והחוב נסגר רק כשהמשתמש מסמן.
- **הודעות:** טקסט חופשי, הודעות מוכנות, גלריית איורים, היסטוריה, ומסך הודעה שנפתח מלחיצה על התראה. ל-Push דרושה הגדרת Firebase (למטה).

### הגדרת התראות Push (חד-פעמי)

1. ב-https://console.firebase.google.com צור פרויקט, והוסף אפליקציית Android עם החבילה `com.dalipay.app`. הורד את `google-services.json`.
2. Project settings ← Service accounts ← Generate new private key (קובץ JSON).
3. Secrets ב-GitHub (Settings ← Secrets and variables ← Actions):
   - `GOOGLE_SERVICES_JSON` — תוכן הקובץ `google-services.json`.
   - `FCM_SERVICE_ACCOUNT_JSON` — תוכן קובץ ה-JSON של חשבון השירות.
   - `SUPABASE_ACCESS_TOKEN` — טוקן אישי מ-https://supabase.com/dashboard/account/tokens.
4. Actions ← **Deploy Backend** ← Run workflow (מריץ את המיגרציה ומפרסם את הפונקציה `send-push`).
5. Actions ← **Build APK** ← Run workflow.

בלי Secrets אלה האפליקציה נבנית ועובדת, אבל ההודעות מופיעות רק באפליקציה ולא כהתראה.

### בדיקות

- `node scripts/unit-tests/run.mjs` — חישובי כסף ושרת ההתראות (30 בדיקות).
- `bash supabase/tests/run_all.sh` — מיגרציה, הרצה חוזרת והרשאות RLS מול Postgres (62 בדיקות).

## גרסה 1.3 — ממשק חדש (WebView) על אותו Supabase

הממשק נבנה מחדש כמסך בית יחיד (HTML/CSS/JS) שרץ בתוך WebView. האפליקציה, שם החבילה (`com.dalipay.app`) ומפתח החתימה נשארו זהים, לכן ה-APK מחליף את הקיים.

```
webui/index.src.html     הממשק (מקור האמת). תמונות ב-webui/img
scripts/build-webui.mjs  בונה src/webui.generated.js (HTML יחיד עם תמונות מוטמעות)
src/bridge.js            כל הגישה ל-Supabase: כניסה, קבוצה, חובות, תשלומים, מוצרים, פתקים, זמן אמת
App.js                   WebView + חיבור הגשר
```

- אחרי שינוי ב-`webui/` מריצים `node scripts/build-webui.mjs` (ה-workflow עושה זאת אוטומטית).
- בדיקות: `node scripts/unit-tests/bridge.mjs` (גשר מול שרת מדומה עם שני משתמשים).
- בדיקת ממשק מלאה בשני דפדפנים: `node scripts/build-webui.mjs && NODE_PATH=$(npm root -g) node scripts/ui-test/e2e.mjs`.
- פתקי התודה נשמרים בטבלת `messages` (השולח והנמען רואים אותם). הסרת פתק מהמסך נשמרת במכשיר בלבד.
